### 1. CEO — Strategy & Value

- **RISK** — No measurable success metric defined (e.g. "reduce circular-triage time from
  X to Y," "catch N system-impacting circulars per quarter that were previously missed").
  Evidence: `decisions.md` #10 states the problem well but stops at qualitative framing.
  Action: define one metric before treating this as done, even informally.
- **NIT** — "Why now" isn't addressed anywhere (why build this in this 5-day window vs.
  continuing to read circulars manually). Low stakes for a take-home; would matter for a
  real internal pitch.

### 2. CTO — Architecture & Technical Direction

- **RISK** — SQLite is the default `DATABASE_URL`, including implicitly for anything
  deployed to satisfy the submission's "URL we can test" requirement. SQLite's single-writer
  lock will contend under concurrent uploads once a background task and a request both touch
  the DB. Evidence: `app/config.py` `database_url` default. Action: set `DATABASE_URL` to
  Postgres explicitly before/at deploy time; this is already documented as swappable, but
  the default is silently the wrong choice for anything beyond a personal demo.
- **RISK** — No DB migration tool (`Base.metadata.create_all` only, `app/database.py`).
  Fine today because of the deliberate EAV design (decision #5), but `Document` and
  `ReviewItem` gained a column this session (`original_value`) with no migration path other
  than "drop and recreate" — acceptable pre-launch, a real gap post-launch.
- **NIT** — Repo-suggestion's local index does a full O(n) linear scan per search
  (`repo_index.py::search`). Fine at the scale a local codebase index actually has; already
  implicitly accepted in decision #11 but not stated as a scaling limit there explicitly.

### 3. CIO — Operations, Security & Compliance

- **ACCEPTED (was BLOCKER, reclassified 2026-07-27)** — No AuthN/AuthZ anywhere. Every
  endpoint — upload, review resolution, `/repo-index/build`,
  `/documents/{id}/suggest-changes` — is callable by anyone who can reach the URL. Accepted
  for this graded demo submission specifically (precedent cited: public take-home demos
  commonly ship without auth, e.g. interviewstreet/hiring-agent) — see decisions.md #13.
  Stated plainly in the README's security-note section rather than silently ignored.
  Reverts to BLOCKER immediately if this project is ever used beyond grading.
- **RISK** — `CORSMiddleware` is configured `allow_origins=["*"]` (`app/main.py`). Combined
  with the auth gap above, this is a materially worse exposure than either issue alone.
- **RISK** — No audit trail of *who* resolved a review item or corrected a classification.
  `ReviewItem` now records the original AI value (fixed this review, see Software Engineer
  lens) but there's no reviewer identity field. For anything compliance-adjacent, "who
  overrode the model and when" matters, not just "what changed."
- **QUESTION** — What's the retention policy for uploaded circular PDFs and their extracted
  data? Currently indefinite, unencrypted on local disk (`UPLOAD_DIR`). Not necessarily wrong
  for a take-home, but undefined.

### 4. CFO — Cost & Resource Economics

- **QUESTION** — No per-document cost estimate or cap. Every upload triggers a paid Claude
  API call (when `LLM_PROVIDER=anthropic`) with no rate limit or daily quota. At low personal
  volume this is a non-issue; worth a stated assumption if this ever runs unattended.
- **RISK** — No cost/rate control on `/documents` uploads specifically — nothing stops a
  misbehaving client (or a bug in a future scraper) from uploading in a loop and generating
  unbounded LLM spend.

### 5. Business Admin — Process & Adoption

- **RISK** — The review queue — the one place a human actually interacts with this system —
  has no UI, only `curl`/`/docs`. Already flagged honestly in the README's "what's not here"
  section; repeating here because it's the single highest-leverage adoption blocker.
- **QUESTION** — No notification path when a system-impacting circular lands. An engineer
  has to remember to poll `/review/queue` and `/query/documents?system_impacting=true`. The
  core value proposition ("catch the circular that would otherwise get missed") is
  undermined if catching it still requires someone to remember to check.

### 6. Data Analytics — Measurement & Data Quality

- **RISK (found + fixed this review)** — Resolving a review item with `action=correct`
  previously overwrote `ExtractedField.field_value` directly, destroying the model's
  original prediction with no record of what it had guessed. That pair (predicted vs.
  human-corrected) is exactly the labeled data needed to ever evaluate or retune the
  confidence thresholds decision #4/#10 already admit are unvalidated priors. **Fixed**:
  `ReviewItem.original_value` now captured at creation time and preserved through
  correction; regression test added (`test_review.py`).
- **QUESTION** — Even with the fix above, nothing aggregates corrections across documents
  yet — the data exists per-row but there's no query/report surfacing "how often was
  `impact_area` corrected, and in which direction" to actually inform threshold tuning.

### 7. Data Scientist — Model & Experimentation Feasibility

- **QUESTION** — `REVIEW_CONFIDENCE_THRESHOLD` (0.75) and `REPO_SIMILARITY_THRESHOLD`
  (0.35) are stated priors, not tuned against any labeled set — already disclosed honestly
  in decisions #4 and #11. Restating here because "disclosed" isn't "resolved": there's no
  offline eval harness even sketched for when a labeled set (e.g. from the fix above)
  becomes available.
- **N/A** — No training/model-building involved; this is inference-only against a hosted or
  local LLM.

### 8. Software Engineer — Implementability & Quality

- **BLOCKER (found + fixed this review)** — `_normalize()` assumes every field arrives as
  a `{value, confidence, source_note}` object. A model returning a bare string for a field
  (syntactically valid JSON, wrong shape) raised an unhandled `AttributeError` that
  propagated out of the `BackgroundTasks` job uncaught — `pipeline.process_document` only
  catches `ExtractionError`, so the document was left in `PROCESSING` permanently: not
  failed, not retryable, not visible as broken. This is precisely the "handled the real
  world, not the happy path" failure mode the project otherwise takes seriously. **Fixed**:
  `extract_document()` now wraps normalization and re-raises as `ExtractionError`;
  regression test added (`test_extraction.py::test_malformed_field_shape_raises_extraction_error_not_unhandled_exception`).
- **RISK** — No structured logging/observability beyond `error_message` on the `Document`
  row. A production instance would want request logging, at minimum for the LLM call
  latency/failure rate.
- **NIT** — `requirements.txt` pins exact versions (`==`) but not hashes; acceptable for a
  demo, would want `pip-compile`/lockfile discipline for anything longer-lived.

### 9. Engineering Manager — Execution Risk

- **BLOCKER** — Neither a deployed URL nor a pushed GitHub repository exists yet. Both are
  explicit, non-negotiable line items in "What we expect" in the assignment brief. Everything
  else in this review is about quality of what's built; this is about whether it's
  submittable at all yet.
- **RISK** — Single-agent, serial build throughout (appropriate for this project's size —
  `plan-workflow`'s parallel-write/choke-point machinery would be overkill here) — flagging
  only because Phase 2's execution-strategy section would otherwise be empty; correctly N/A
  for a project this size, not an oversight.
- **NIT** — Follow-up work is well-tracked (`decisions.md`'s "what was cut" sections read
  like a proper backlog already) — noting as a positive, not a finding requiring action.

## Recommendation

**Do not treat as ready to submit** until the two BLOCKERs outside this review's own scope
are closed: deploy it somewhere reachable, and push the repo. The auth gap (CIO/CTO) is a
BLOCKER for anything beyond the grading deployment specifically, but for a time-boxed
take-home graded by a small number of reviewers, a documented, explicit "no auth, single-
tenant demo" caveat in the README is a defensible short-term mitigation — silently shipping
it with no auth *and* no caveat is not.

The two implementation bugs this review surfaced (stuck-`PROCESSING` on malformed LLM
output, destroyed original value on correction) are fixed and tested as of this review —
included here anyway because *how* they were found (systematic lens-by-lens review, not
"noticed while doing something else") is itself worth recording in `decisions.md`.
